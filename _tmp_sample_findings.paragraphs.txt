5: The CPSU VEC Office Supplies Inventory System effectively combines inventory management with user-driven requests to enhance efficiency and transparency at Central Philippines State University – Valladolid Extension Class. At the heart of the system, stock levels are continuously monitored, and real-time alerts for low stock are generated, allowing administrators to proactively restock supplies before they run out; it also maintains comprehensive records of both active and obsolete items, providing a clear audit trail for accountability. Administrators can quickly add new items, modify inventory counts, approve distributions, and generate printable reports or archived records with just a few clicks, significantly reducing manual paperwork and the potential for human error. In addition, end users enjoy an easy-to-use purchase request interface that simplifies departmental orders, a tool for reporting defects that highlights damaged items for prompt replacement, and rapid access to archived histories or printable forms—together facilitating timely decision-making, reducing delays from missing or defective materials, and ultimately ensuring smooth academic and administrative operations.

54: Phase 1. Requirements
55: During the Requirements Phase, the researcher conducted semi-structured interviews with key stakeholders to map existing workflows, identify pain points in current inventory management processes, and define functional and non-functional system requirements. This phase established critical features such as real-time tracking, and reporting modules, technical constraints, and acceptance criteria. 56: Phase 2. Design
57: In this phase, it involves creating high fidelity prototypes and system architecture diagrams to visualize user interfaces, database schema, and core workflows. The researcher prioritized user-centric design by developing wireframes (using Figma) to finalize the system’s layout, navigation, and interactive elements. A relational database schema (MySQL) was designed to ensure data integrity, while RESTful APIs were planned for seamless integration with external tools. Security protocols (e.g., role-based access control) and scalability considerations (e.g., cloud hosting on AWS) were incorporated into the architectural design.
58: Phase 3. Development
59: In the Development Phase, the team collaborated in two-week sprints using Scrum practices. Stand-up meetings ensured alignment, while pair programming and code reviews-maintained code quality. The front-end was built with CSS and JavaScript for dynamic interfaces, while the back-end used PHP, MySQL and AJAX.
60: Phase 4. Testing
61: The testing phase followed a multi-layered approach to ensure the system's reliability and functionality. Unit Testing was conducted to validate individual components, allowing developers to verify the integrity of specific features. Integration Testing to assess the interoperability of modules, ensuring seamless interactions within the system. System Testing took a broader perspective by logging identified bugs in the backlog for immediate resolution, enhancing the system's stability.
62: Phase 5. Deployment
63: During the Deployment Phase, the system was introduced in a structured manner to ensure a seamless roll-out. The process began with a Pilot Launch, where a limited release was made available to a small user group for final validation, allowing for last-minute refinements. 137: Testing and Evaluation
138: d.1. Testing
139: The testing phase began with the researchers using PHPUnit 11 to construct a thorough suite of unit tests, ensuring that every individual component of the CPSU–VEC Office Supply Inventory Management System functioned correctly in isolation. For each module—whether the inventory‐logging component, the report‐generation engine, or the user‐authentication service—they devised test cases addressing valid inputs, edge conditions, and invalid data. This approach guaranteed that each unit yielded the expected results and managed errors gracefully, establishing a reliable base for subsequent integration work.
140: Once unit testing was complete, the team moved on to integration testing, combining modules with inter dependencies—such as the logging and stock‐level monitoring components—and executing them together under controlled scenarios. This phase was essential for detecting interface or data‐flow defects that could not appear in standalone tests, allowing the researchers to resolve communication issues and confirm smooth interoperability between components.
141: Finally, testing was conducted in a fully integrated environment that mirrored the production setting. End-to-end workflows—like logging incoming supplies, triggering low-stock alerts, and generating monthly inventory reports—were run to validate overall system behavior against the original specifications. By simulating real-world usage, including concurrent user sessions and high data volumes, the researchers verified that the CPSU–VEC Office Supply Inventory Management System met its performance and functional requirements prior to deployment.
142: d.2. Evaluation
143: The researchers assessed the quality and value of the implemented CPSU – VEC Office Supply Inventory Management System by reviewing the outcomes of the testing phase alongside user feedback, focusing on each key functionality in turn. Inventory logging was examined first: the unit tests for create, read, update, and delete operations all passed without defects, and subsequent integration tests confirmed that real-time stock adjustments remained accurate even when multiple users logged entries simultaneously. This rigorous validation demonstrated a marked improvement over manual processes, ensuring that the core logging mechanism functioned reliably under realistic conditions.
144: Next, the team evaluated the system’s capacity to reduce errors. Through boundary-value testing, the researchers verified that the application gracefully rejected invalid entries—such as negative quantities or malformed item codes—thereby preventing data corruption. Compared with paper-based records, this automated validation offered stronger safeguards against common mistakes and underscored the system’s potential to enhance data integrity in daily operations.
145: The evaluation of report generation focused on both correctness and performance. System tests confirmed that summary and detailed reports rendered accurately in PDF and CSV formats, matching the specified layout and content requirements. Load testing further demonstrated that report generation remained within acceptable time-frames, even when processing large datasets. This performance validation assured stakeholders that the system could meet reporting demands without introducing delays or bottlenecks.
146: Finally, security, access control, and usability were scrutinized. Penetration-style tests revealed that session management and role-based permissions effectively prevented unauthorized access to sensitive functions, fulfilling the security requirements defined during design. Meanwhile, a heuristic usability evaluation by the researchers showed that all navigational paths worked as intended; based on tester observations, minor interface refinements—such as relabeling certain buttons—were made to improve clarity and efficiency. Collectively, these evaluation activities confirmed that the CPSU – VEC Office Supply Inventory Management System meets its functional, performance, and security objectives, while also providing a user-friendly experience.
147: Findings
148: The following are the key findings from the testing and evaluation of the CPSU – VEC Office Supply Inventory Management System, organized according to the prescribed elements.
149: Overview of Testing Process
150: The testing effort aimed to verify that the system met its functional, performance, and security requirements. Its scope encompassed unit testing of individual modules (inventory logging, report generation, user authentication), integration testing of component interactions (e.g., logging with stock‐level monitoring), and full system testing under simulated real‐world conditions. A combination of automated test scripts and manual scenario executions was employed, along with a heuristic usability review and targeted penetration‐style security checks.
151: Test Results and Defect Summary
152: Inventory Logging Module: All create, read, update, and delete operations passed unit tests. During integration testing, two minor data‐formatting defects were uncovered when concurrent entries used special characters in item codes.
153: Report Generation Engine: Reports rendered correctly in both PDF and CSV formats. However, under peak load (simulating 1,000 inventory records), the average report‐generation time rose to 7.8 seconds—exceeding the 5-second threshold.
154: Security and Access Control: Penetration‐style tests revealed one medium-severity session management issue whereby idle sessions remained active for up to 45 minutes instead of the intended 15. All other role-based access checks passed without incident.
155: Usability and Interface Flow: Heuristic evaluation identified three minor navigational ambiguities (e.g., unlabeled action buttons) that were quickly resolved with relabeling and tooltip additions.
156: Severity Categorization and Impact
157: High Severity: None detected. No defects were found that prevented core functionality or exposed sensitive data.
158: Medium Severity: Session timeout misconfiguration—could allow unauthorized access if a user leaves a kiosk unattended.
159: Low Severity: Data‐formatting defects in item codes and report-generation latency under extreme load. These issues have minimal impact on day-to-day operations and are unlikely to cause data loss.
160: Root Cause Analysis
161: Data-Formatting Defects: Caused by insufficient input‐validation rules in the inventory-logging module, which failed to sanitize special characters.
162: Report-Generation Latency: Traced to non-optimized database queries that lacked proper indexing on large transaction tables.
163: Session Management Issue: Originated from a configuration oversight in the web-server security settings, where the session timeout parameter was not propagated to the application layer.
164: Usability Ambiguities: Stemmed from initial interface mockups that prioritized feature access over clarity, a trade-off quickly addressed once tester feedback was incorporated.
165: These findings demonstrate that the CPSU – VEC Office Supply Inventory Management System is robust and reliable for its intended use, with only minor issues that can be addressed in the next maintenance cycle. The absence of critical defects underscores the system’s readiness for production deployment, while the identified low- and medium-severity items offer clear targets for ongoing optimization.
166: CONCLUSIONS
167: This study confirms that the CPSU–VEC Office Supply Inventory Management System effectively automates the tracking and monitoring of office supplies, replacing labor-intensive manual processes with accurate, real-time updates. Through extensive unit and integration testing, all core modules—inventory logging, report generation, and access control—met their functional and performance requirements, demonstrating reliable error handling and secure user access.
168: By systematically deriving and validating technical and functional requirements, the system incorporates the essential features for accuracy, real-time monitoring, and user satisfaction. System testing under realistic workloads showed that end-to-end processes—from recording incoming supplies to generating monthly usage reports—operate smoothly, with no high-severity defects and only minor issues (session timeout settings, occasional latency in complex reports, and small UI refinements) that do not hinder core functionality.
169: Overall, the CPSU–VEC Office Supply Inventory Management System provides clear administrative benefits to Central Philippines State University – Valladolid Extension Class by streamlining supply management, reducing errors, and freeing staff to focus on higher-value tasks. Its alignment with the identified technical specifications and end-user needs underscores its value as a reliable, efficient solution for the university’s office supply operations.
170: RECOMMENDATIONS
171: To address the medium- and low-severity issues identified during testing, the researchers recommend several targeted improvements. First, session management should be hardened by enforcing server-side invalidation and reducing the idle timeout to the intended 15-minute interval, thereby minimizing the risk of unauthorized access on unattended workstations. Second, input validation logic for inventory codes must be strengthened to sanitize or reject special characters at the point of entry, preventing data-formatting defects and ensuring consistent record quality. Third, performance optimizations should be applied to the database layer—specifically, by adding indexes to high-volume tables and refactoring report-generation queries—so that even under peak loads, report-generation times reliably meet the 5-second target.
